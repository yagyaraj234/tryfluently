# Domain Docs

Fluently has one product context across `apps/api`, `apps/web`, `packages/db` and `packages/ui`.

Before exploring or changing a domain flow, read the relevant terms in the root [glossary](../../GLOSSARY.md) and decisions in [docs/adr/](../adr/). Use those terms in code, UI, issues and tests. When a concept is missing, check the current schema and callers before adding a term.

If a proposed change conflicts with an ADR, name the conflict and the reason to revisit the decision. Dated notes in [docs/research/](../research/) record research and proposals; current code and ADRs describe the implemented behavior.
